# 🚀 CRM System 🚀

[Русский](README.md) | [English](README.en.md)

Веб-приложение CRM для сервисных центров, предназначенное для управления заказами, клиентами, услугами, финансовыми операциями, документами и складскими запасами.

Проект разработан на Python с использованием Django и PostgreSQL. Для контейнеризации и развёртывания используются Docker, Gunicorn и Nginx.

## 🧾 О проекте 🧾

Основная цель проекта - объединить ключевые рабочие процессы сервисного центра в одной системе.

CRM предоставляет инструменты для управления заказами, учёта финансовых операций, работы с документами, управления услугами и отслеживания складских запасов.

## 🔑 Основные возможности 🔑

- **Управление заказами** - создание заказов, изменение статусов, расчёт стоимости и скидок.
- **Работа с клиентами** - поиск и использование информации о клиентах.
- **Управление услугами** - создание услуг и категорий услуг.
- **Финансовый учёт** - регистрация доходов и расходов, проведение платежей и просмотр финансовой истории.
- **Работа с документами** - создание, редактирование и формирование документов на основе HTML-шаблонов.
- **Складской учёт** - учёт поступлений, списаний и истории движения товаров.
- **Профили пользователей** - управление личной информацией и данными сотрудников.
- **Динамические формы** - создание и настройка форм для различных рабочих процессов.

## Структура проекта

Проект разделён на Django-приложения, каждое из которых отвечает за отдельную область функциональности.

| Приложение | Назначение |
|---|---|
| `auth_registration` | Регистрация и авторизация пользователей |
| `profile_user` | Профили пользователей, сотрудники и документы |
| `orders` | Заказы, статусы, платежи и формирование документов |
| `finance` | Финансовые операции и учёт баланса |
| `services` | Управление услугами и категориями услуг |
| `storage` | Складской учёт и история движения товаров |
| `crm_system` | Основные настройки и конфигурация Django |

## 📰 Архитектура 📰

Приложение использует следующую схему взаимодействия компонентов:

```text
             Пользователь
                  |
                  v
                Nginx
                  |
                  v
           Gunicorn / Django
                  |
                  v
              PostgreSQL
```

Docker Compose управляет тремя основными сервисами:

- `web` - Django-приложение, запущенное через Gunicorn.
- `db` - база данных PostgreSQL.
- `nginx` - обратный прокси для обработки HTTP- и HTTPS-запросов.

## ▶️ Локальный запуск ▶️

### ❗ Требования ❗

- Git
- Docker
- Docker Compose

### 1. Клонирование репозитория

```bash
git clone https://github.com/SergeyBalatskiy/crm_system.git
cd crm_system
```

### 2. Настройка переменных окружения

Создайте файл `.env` в корневой директории проекта:

```env
SECRET_KEY=your-django-secret-key

POSTGRES_DB=crm_db
POSTGRES_USER=crm_user
POSTGRES_PASSWORD=your-secure-password

POSTGRES_HOST=db
POSTGRES_PORT=5432
```

Укажите собственные значения переменных!

### 3. Сборка и запуск приложения

Для локального запуска базы данных и Django-приложения выполните:

```bash
docker compose up -d --build db web
```

При запуске контейнера `web` Django автоматически выполняет миграции базы данных перед запуском Gunicorn.

### 4. Создание администратора

```bash
docker compose exec web python manage.py createsuperuser
```

### 5. Открытие приложения

Приложение будет доступно по адресу:

```text
http://localhost:8000
```

## 📌 Развёртывание на сервере 📌

Для production-развёртывания используются Docker Compose, Gunicorn, Nginx и PostgreSQL.

Конфигурация Nginx предусматривает обработку HTTP- и HTTPS-запросов. Для работы HTTPS необходимо предварительно настроить домен и SSL-сертификаты в директории Certbot.

Для обновления приложения после получения изменений из GitHub:

```bash
git pull
docker compose up -d --build
```

Проверить состояние контейнеров:

```bash
docker compose ps
```

Посмотреть логи Django-приложения:

```bash
docker compose logs -f web
```

Перед обновлениями, затрагивающими базу данных, рекомендуется создавать резервную копию PostgreSQL.
